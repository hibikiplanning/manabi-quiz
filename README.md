# コード穴埋めクイズ — React × Python API（見本）

プログラミングを学ぶための、**コードの穴埋めクイズ**です。
**「書いたら（選んだら）どうなるか」がその場で見える**ことを一番大切にしています。

- **こども**: コードの □ に入るものを**選ぶ**。選んだ瞬間にそのコードを実際に動かし、「めざす けっか」と見比べられる。ヒントつき。考えてから答えるほど ★ が増える
- **おとな**: 関数の中身を**自分で書く**。実行するとテストが走り、1件ずつ ✓／✗ と「期待した値・実際の値」が出る。合格すると解答例と解説

画面は **React**、出題と合否の判定は **Python（FastAPI）の API** が担当します。

## 「どんな入力でも壊れない」ための作り

おとな向けは自由にコードを書けるので、無限ループ・書き間違い・意図しない動きのコードも入ってきます。

| 起きうること | 対策 |
|---|---|
| 無限ループ | 毎回あたらしい **Web Worker**（画面とは別の実行場所）で動かし、**1.5秒で Worker ごと止める**。画面は固まらない |
| 書き間違い・実行時エラー | すべて捕まえて「結果」として表示。こども向けは言葉をやさしく言い換える（例:「こんにちは」という なまえが みつからないよ） |
| 外への通信 | 実行前に `fetch` などの通信の入口を塞ぐ。画面（DOM）にも触れない |
| 大量の出力 | `console.log` は200行・1万文字で打ち切り |
| **サーバーでの実行** | **しない**。ユーザーのコードはブラウザの中だけで動き、サーバーは返り値を期待値と比べるだけ |

判定の注意点も押さえています。Python では `True == 1` が成り立ちますが、JavaScript の `true` と `1` は別物なので、真偽値は厳密に比べます（`isPalindrome` が `1` を返したら不合格）。

## 正解はサーバーだけが持つ

- 出題時に画面へ渡すのは、問題文・コードのひな形・選択肢・ヒント・テストの**入力**だけ
- こどもの正解、おとなのテストの**期待値**と**解答例**はサーバーの中。画面の裏側を覗いても答えは分からない
- 選択肢の並び順は毎回変わるが、答え合わせは元の番号で行う

## 問題の足し方

`backend/questions.json` に1つ足すだけです（コードの変更は不要）。

**こども（選択式）**
```json
{
  "id": "k07", "level": "kids", "title": "ひきざん",
  "question": "7 と ひょうじ したい。□ に はいる かずは？",
  "template": "console.log(10 - □);",
  "choices": ["2", "3", "4", "7"],
  "answer": 1,
  "goal": "7",
  "hint": "10 から いくつ ひくと 7 に なるかな？",
  "explanation": "10 - 3 = 7 だよ。"
}
```
- `template` には □ をちょうど1つ。`answer` は `choices` の **0 から数えた番号**
- `goal` は正解を入れたときに表示される結果（複数行は `\n` で区切る）

**おとな（コード入力）**: `func`（関数名）・`template`（書き始めのコード）・`tests`（`input` は引数の配列、`expected` は期待する返り値）・`sample`（解答例）を書きます。

### 問題を足したら、2つの検査を通す

```bash
cd backend && python -m pytest -q      # API とデータの形の検査（26件）
cd frontend && npm run check           # 問題の中身を実際に JavaScript で動かして検査
```

`npm run check` は次を確かめます。

- こども: 正解を入れると `goal` がそのまま出るか／**不正解なのに `goal` と同じ結果になる選択肢がないか**（あると問題として成り立たない）
- おとな: 解答例がすべてのテストを通るか／**書き始めの状態で合格してしまわないか**（テストが甘くないか）

わざと壊した問題（正解の取り違え・負の数で間違える解答例・甘すぎるテスト）を入れて、すべて検出できることを確認しています。

## 動かし方

必要なもの: Python 3.10 以上、Node.js 20.19 以上（22 系なら 22.12 以上）

### 1. API（Python）

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   /  macOS・Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --port 8787
```

`http://127.0.0.1:8787/docs` で API の説明と試し打ちの画面が開きます（FastAPI の自動ドキュメント）。

> ポートを 8787 にしているのは、Windows では 8000 番が予約されていて使えない環境があるためです。

### 2. 画面（React）

別のターミナルで:

```bash
cd frontend
npm install
npm run dev
```

`http://localhost:5173` を開きます。開発中は `/api` への通信を Vite が 8787 番へ中継します（`vite.config.js`）。

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/levels` | レベルの一覧（`kind`: `choice`＝選択式／`code`＝コード入力）と問題数 |
| GET | `/api/quizzes?level=kids&limit=5` | 問題を出す（**正解・期待値・解答例は含まない**）。`seed` で出題順を固定できる |
| POST | `/api/answer` | こども: `{"question_id": "k01", "choice_id": 1}` → 正誤・正しい選択肢・解説 |
| POST | `/api/judge` | おとな: ブラウザで実行した各テストの返り値 `{"question_id": "a01", "results": [{"value": 6}, ...]}` → テストごとの合否。全部合格なら解答例と解説 |
| GET | `/api/solution/{id}` | おとな: 解答例と解説（あきらめたとき） |

## ファイル

```
backend/
  app.py             API（出題・答え合わせ・判定）
  questions.json     問題（ここを編集して増やす）
  test_app.py        API とデータのテスト
frontend/
  src/runner.js      ユーザーのコードを安全に動かす仕組み（Web Worker・時間制限・通信の遮断）
  src/KidsQuestion.jsx   こども: えらんで ためす
  src/CodeQuestion.jsx   おとな: 自分で書く
  src/Result.jsx     結果（★の合計／合格数）
  scripts/check-questions.mjs  問題の中身の検査
```
